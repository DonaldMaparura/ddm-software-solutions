## What this project is

This is the **DDM Software Solutions** marketing site + **template marketplace**. It is a
multi-page static site that also showcases client website templates, each with a
browsable **live demo** and a purchase/customise flow (PayFast checkout).

Individual template projects live as **sibling folders** next to this repo, e.g.
`C:\Users\admin\IdeaProjects\<ProjectName>`. This repo pulls copies of those builds into
`demos/` so they can be served on GitHub Pages.

## Key files & folders

| Path | Purpose |
| --- | --- |
| `js/templates.json` | The catalogue. One entry per template. Drives the marketplace grid, demo links, checkout, and the sync/capture scripts. |
| `js/templates-page.js` | Renders the marketplace cards from `templates.json`. Demo link is `/demos/<id>/`. |
| `demos/<id>/` | Self-contained static copy of each template, served on GitHub Pages. Generated — do not hand-edit. |
| `img/templates/<id>.png` | Thumbnail shown on the marketplace card. Generated. |
| `scripts/sync-demos.mjs` | Copies each template build into `demos/<id>/`, rewrites root paths, injects the customiser bridge. `npm run sync:demos` |
| `scripts/capture-templates.mjs` | Screenshots each demo into `img/templates/<id>.png` with Playwright. `npm run capture:templates` |
| `server/demo-utils.mjs` | Shared path-rewrite + customiser-bridge logic used by the server and sync script. |

## How to add a new template (the workflow)

Given a sibling project folder (e.g. `C:\Users\admin\IdeaProjects\<ProjectName>`):

1. **Inspect the project.** Find the built/servable entry point:
   - static site with `index.html` at root → `entry: "."`
   - Next.js export → `entry: "out"`
   - Vite/other build → `entry: "dist"` or `"public"`, etc.

2. **Add an entry to `js/templates.json`:**

```json
{
  "id": "kebab-case-id",
  "name": "Display Name",
  "industry": "Restaurants",
  "category": "restaurant",
  "price": 499,
  "customisePrice": 499,
  "summary": "One-line marketing description.",
  "features": ["Responsive", "SEO Ready", "Gallery", "Reservations"],
  "projectPath": "<ProjectName>",
  "entry": ".",
  "thumbnail": "img/templates/kebab-case-id.png",
  "demo": true,
  "hostingPrice": 1999
}
```

   - `projectPath` is the sibling folder name (relative to `../`).
   - `category` must match a marketplace filter chip (`restaurant`, `beauty`,
     `automotive`, `corporate`, `medical`, `construction`, `school`, `law`, ...).
   - Set `demo: true` + a valid `entry` for a live demo. Use `demo: false` / `entry: null`
     for "request demo" placeholders.

3. **Add the same id/path/entry to the `TEMPLATES` array in `scripts/capture-templates.mjs`**
   (so the thumbnail can be captured).

4. **Sync the demo:**

```bash
npm run sync:demos
```

5. **Generate the thumbnail** (single template — the script accepts id args):

```bash
node scripts/capture-templates.mjs <id>
```

   (Omit the id to recapture everything.)

6. **Commit & push** the changes: `js/templates.json`, `scripts/capture-templates.mjs`,
   `demos/<id>/`, `img/templates/<id>.png`.

## Important gotchas

- **Never publish private data.** Source projects may contain sensitive folders/files
  (e.g. `sa-website-leads/`, `leads_crm.csv`, CRM exports). `sync-demos.mjs` copies the
  whole project tree and does **not** skip these. After syncing, delete anything sensitive
  or unused (large `photos/` source folders, videos, duplicate PDFs) from `demos/<id>/`.
- **Relative asset paths** in a template (`assets/...`, `css/...`) resolve correctly under
  `/demos/<id>/` and are left untouched. Only **root-absolute** paths (`/assets/...`) get
  rewritten by `sync-demos.mjs`.
- **Do not hand-edit `demos/<id>/`** — it is regenerated by `sync-demos.mjs` and changes
  will be lost on the next sync.
- Running `npm run sync:demos` re-syncs **all** demos; unchanged ones produce no git diff.
- This is a Windows / PowerShell environment: `&&` is not a valid statement separator —
  chain commands with `;` instead.
